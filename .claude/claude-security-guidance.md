# Security guidance for this repo（PM育成シミュレーション）

security-guidance プラグインのモデルレビューが、ビルトインのチェックに加えて読む追加ガイド。
このリポジトリ特有の脅威モデル。レビュー時に特に厳しく見ること。

## 秘密情報 / APIキー（最優先）
- OpenAI の**標準APIキーはサーバ側のみ**。クライアントへ返す/露出させる変更は必ず指摘。
- クライアントが受け取ってよいのは **ephemeral key だけ**。標準キーをAPIレスポンスやログに含めない。
- `NEXT_PUBLIC_` に鍵・トークン・シークレットを置かない（ビルド時にクライアントへ焼き込まれる）。
- APIキー・ephemeral key・認証情報をログ出力しない。

## サーバ境界
- ephemeral key 発行など秘密を扱う処理は `app/api/**`（サーバ）に置く。
- `"use client"` のファイルから `process.env` の秘密（OpenAIキー等）に触れていないか確認。

## プロンプトインジェクション / 信頼境界
- AIキャラに渡るユーザー入力・モデル出力は**信頼しない**。これらを使ってシステムプロンプトやサーバ秘密を引き出す経路、サーバ側の分岐や権限を変えられる経路がないか見る。
- モデル出力・ユーザー入力を `dangerouslySetInnerHTML` 等でDOMへ挿入しない（XSS）。
- 外部テキスト（モデル応答含む）を `eval`・シェル実行・動的importへ渡さない。

## 注記
これはレビュー用の実施であって決定論的ガードではない。ハードな強制は PreToolUse フック
（`.claude/hooks/`）と CI（`.github/workflows/security.yml`）が担う。
