Download OpenAPI specification:

Player-layer endpoint specification. Corresponds to the Player Endpoint definitions in docs/architecture/components.md. Each endpoint connects to external services or the DB through the Provider layer (AuthProvider / AIProvider / VoiceProvider / Store).

Authentication

Register a new account

  1. Receive a RegisterRequest (email / credential / username)
  2. Call AuthProvider to establish a session
  3. Return AuthResult (id / role) with 201
  • If username is omitted, the server sets the local part of the email address (before @)
  • After successful registration, the user is already signed in (register + sign-in combined)
  • role is fixed to "player" at registration

required
string <email>

required
string >= 8 characters

  • Roles are fixed (one each of user_dept / manager / dev_member)

Session issuance

Issue a Realtime session bundle

  1. Receive a RealtimeSessionRequest (stakeholderId / project / stakeholders / documents / callLogs)
  2. Assemble the system prompt server-side (common_base + role-specific + conversation memory + cross-stakeholder dossier)
  3. Call VoiceProvider ({ instructions, voice, tools })
  4. Return RealtimeSessionResponse (value / model / sessionUpdate) with 200
  • Internal state such as rootCause is baked into the prompt but not sent to the client
  • The ephemeral key (value) is short-lived. The client uses it to connect directly to the OpenAI Realtime API

Evaluation

Generate an overall evaluation and save the result

  1. Receive an EvaluateRequest (project / stakeholders / callLogs)
  2. Call AIProvider(evaluatePrompt)
  3. Obtain ScoreResult (score / headline / good / improvements / comment)
  4. Call Store.results.save() to persist the result (the evaluation response is returned even if persistence fails)
  5. Return ScoreResult with 200

  2. Obtain the account ID via AuthProvider.getPrincipal()
  3. Call Store.accounts.get(id)
  4. Return AccountProfile (id / email / username / role) with 200
