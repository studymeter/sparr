Sparr Player Endpoints (1.0.0)

Download OpenAPI specification:

Player-layer endpoint specification. Corresponds to the Player Endpoint definitions in docs/architecture/components.md. Each endpoint connects to external services or the DB through the Provider layer (AuthProvider / AIProvider / VoiceProvider / Store).

Authentication: the canonical adapter handler is app/api/auth/[...auth] (providers.auth.handlers delegation, framework-managed by the Auth adapter). Credential sign-in (/api/auth/signin) and sign-out (/api/auth/signout) are custom routes and are documented below. The session route and OAuth provider delegation use the URL scheme derived from the adapter (e.g. Auth.js: /api/auth/session) and are not listed here.

CSRF: protected via SameSite cookie attribute (Auth.js-independent). No X-CSRF-Token header is required.

Business endpoints assume an authenticated principal obtained via getPrincipal().

Authentication

Register a new player account

Delegates to providers.auth.register().

  1. Accept RegisterRequest (email / credential / username?)
  2. Call providers.auth.register() — validates, checks for duplicates, persists account
  3. Return AuthResult (id / role) with 201; role is fixed to "player"
  • If username is omitted, the local part of the email address is used
  • After successful registration the user is already signed in (register + sign-in combined)

Sign in with email and credential

Delegates to providers.auth.signin().

  1. Accept SignInRequest (email / credential) — 400 if either is missing
  2. Call providers.auth.signin() to verify the credential and establish the session
  3. Load the account via Store.accounts.get() and return AccountProfile with 200
  • Returns 401 with error "invalid_credential" when the email/credential pair does not match

Session issuance

Issue a Realtime session bundle

  1. Receive a RealtimeSessionRequest (stakeholderId / project / stakeholders / documents / callLogs)
  2. Assemble the system prompt server-side (common_base + role-specific + conversation memory + cross-stakeholder dossier)
  3. Call VoiceProvider ({ instructions, voice, tools })
  4. Return RealtimeSessionResponse (value / model / sessionUpdate) with 200
  • Internal state such as rootCause is baked into the prompt but not sent to the client
  • The ephemeral key (value) is short-lived. The client uses it to connect directly to the OpenAI Realtime API

Tickets

Get the current user's ticket snapshot

  1. Obtain the principal via providers.auth.getPrincipal()
  2. Return 401 (error "unauthenticated") if the principal is anonymous
  3. Sync the registration grant if owed, then compute the snapshot via getTicketSnapshot()
  4. Return TicketSnapshot (balance / ledger) with 200
  • ledger holds up to the 20 most recent ticket rows

  1. Resolve principal via providers.auth.getPrincipal()
  2. Return 401 for anonymous, 403 for non-player roles
  3. Accept optional BillingCheckoutRequest (quantity: integer 1..1000; default 1)
  4. Resolve (or create) Stripe customer id for the player account
  5. Create Stripe Checkout session in payment mode (unit price × quantity)
  6. Return the hosted checkout URL with 200
